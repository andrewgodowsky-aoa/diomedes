## 4. Cost envelopes for sample workflows

All figures below are computed by script, not by hand (calculation discipline, Pillar 1; hard rule 6). ## 5. Cost levers

**Caching.** Anthropic, OpenAI and Google each publish cache-hit discounts of roughly 90% off base input price (Anthropic 0.1x standard / 0.025x on Fable 5.1; OpenAI ~10% of standard input; Google bills cache storage separately, at $0.50 per 1M tokens per hour on 3.8 Flash through 2026, rather than as a hit-rate discount) (09a findings 1-2; ME-03 row 22, corrected, which supersedes 09a's unverified $0.075–$0.15/MTok figure). DeepSeek and Kimi structure this as a first-class cache-hit/cache-miss price split rather than an opt-in feature (09a findings 4-6). §4.5 shows the mechanism at a 70%-hit synthetic assumption. **Caveat carried from §2: Anthropic's API BAA excludes Batch, Files, Skills, Code Execution, Computer Use and Web Fetch (04b c2)** — caching itself is not excluded, but the batch discount below is unavailable on any workflow that must stay inside a HIPAA BAA (OD-22).

**Batching.** A flat ~50% off both input and output, available at Anthropic, OpenAI, Google and (per DeepSeek's peak/off-peak structure) DeepSeek. Strong fit for the operating brief, schedule check and regression run in §4 — all repeated-context, non-urgent-latency workloads — and weak fit for anything a customer is waiting on synchronously (a quote draft, a review response). Not available for a regulated-vertical workload that must stay inside an Anthropic API BAA, since Batch is one of the BAA's named exclusions (04b c2; see §6).

**A routing ladder.** §3's verified prices span roughly 30–100x on list input/output price between the cheapest usable tier (GLM-5.3-Flash, DeepSeek off-peak cache-hit) and the most expensive (Fable 5.1, gpt-6-astra) (09a Implication 1). A router that moves routine, bounded work (classification, structured extraction, first-pass drafting — 09b §6) down that ladder as models improve is a genuine lever, but only if payer attribution is tracked per call (Pillar 7); otherwise "managed inference" becomes an unmeasured shared cost, in tension with Pillar 10. List prices span about 67x on input and 100x on output between GLM-5.3-Flash and Fable 5.1 (input $10 / $0.15 = 66.7; output $50 / $0.50 = 100). On Artificial Analysis's measured cost to run its Intelligence Index, the spread is about 42x (Fable 5.1 $7.63 / GPT-5.6 Luna $0.18 = 42.4) for an index gap of 38 to 53. Two models with the same top score of 53 differ about 2.3x (Fable 5.1 $7.63 / GPT-6 Astra $3.26 = 2.34), so measured cost per task, not list price, should rank the top tier (ME-03 finding 6, rows 31, 34; ratios recomputed with node). A tiered ladder with a payer per tier is in ME-00 Table 4; it is input to the route-selection gate, not a route. OD-55 proposes refreshing the route candidates and keeping a dated selection record per tier (terms, data terms, benchmark basis, price date, payer), retiring the candidate list at the 2026-09-10 pricing base (removed 2026-09-19) line 71; that base is not edited here.

**Payer attribution per business and workflow (Pillar 7).** What exists today, per `status.ts`: `verified-model` (available) records the actual model name from the runtime's own report on every turn; `usage` (available) shows usage bars from the engine's own reports. What does not exist: token-cost instrumentation tied to a managed-inference payer. `managed-usage` (in-development) implements "budget reservations, settlement, payer checks and accounting records" with deterministic contracts and tests, but carries no entitlement and is not sellable. So per-turn model identity is real today; per-business, per-workflow *cost* attribution for a paid managed route is designed but not operating. Whether every stored trace also carries per-source provenance (which engine and account produced it, and the customer's consent state), so that closed-account outputs can be kept out of any future training set, is not verified in code and is OD-56 (ME-07 section (e), Implication 3).

**Instrumentation on the first live run (Pillar 10).** 09a's central recommendation (Implication 3) is not to guess between the single-call estimate (§4.2) and the agentic-overhead envelope (§4.3), but to instrument actual token usage the first time any workflow in §4 runs against a real business, and revisit both the $15 allowance and the $300/$100 candidate figures once real numbers exist. This document adds nothing to that beyond stating it applies equally to every workflow in this note, not only the ones costed here. The field list for that first run is OD-57 (first-live-run instrumentation spec).

## 6. Data terms as a routing factor

Findings 1-3 in 09a show Anthropic, OpenAI and Google's paid tiers all default to not training on customer data, with brief, bounded abuse-monitoring retention windows rather than a customer-selectable zero-retention default (except where ZDR is separately approved). DeepSeek is the outlier, **stated at the corrected strength only**: its privacy policy gives an opt-out from training use of *personal data*, its separate Open Platform Terms say nothing explicit about training on API inputs or outputs, and it states personal data is processed and stored in the PRC, with downstream developer applications explicitly excluded from its own privacy-policy coverage (09a finding 4, Verification row 10). **Do not state "DeepSeek trains on API data by default"** — that stronger claim was in an earlier draft of 09a and is corrected, not confirmed. Z.ai's API terms promise no use of End User Content without the customer's explicit agreement (medium-high confidence, summarizing fetch), and its DPA describes real-time processing without storage, generally in Singapore (ME-07 row 22; ME-04 row 36). Moonshot/Kimi trains on content by default, with enterprise arrangements available (ME-07 row 21). Mistral's Commercial Terms §4.2 permit no training on Customer Data or Outputs except through a product's opt-in or opt-out default, Feedback, an Order Form, or Labs/Preview use (ME-07 finding 5, row 13). Host data terms for OpenRouter and Groq remain unchecked (§2).

Per Pillar 9 (trust, data choice and billing are architecture), if Diomedes ever defaults a business's work to a specific hosted model without the business choosing it, this spread in data terms — not price — is the more consequential difference between routes. DeepSeek's PRC-storage and opt-out (not opt-in) posture makes it a materially different trust choice from Anthropic, OpenAI or Google's paid tiers, which argues for exposing "which route, whose data terms" as a real, visible control in any managed-inference or routing design, not a backend implementation detail chosen purely on price. The cross-cutting regulated-work implication: a workflow that must stay inside an Anthropic API BAA cannot use the Batch API (§5), which narrows the cost-lever set specifically for the regulated verticals OD-22 is deciding about.

### 7.4 Realistic fit per workload class

Local, small-to-mid open-weight models are a credible fit for: classification/routing of incoming text (support tickets, emails, form submissions); structured extraction from documents into a fixed schema; first-pass drafting a human then edits; and local semantic search over the business's own documents — bounded, well-specified tasks where Pillar 8's human-review safety net matters more than raw model strength (09b §6).

Local models are a poor fit for: open-ended multi-step reasoning, fast-changing world knowledge, complex multi-document synthesis over very long context, and any task where a wrong answer carries material rework or compliance exposure that a smaller model is statistically more likely to produce than a frontier hosted model. For that class, the honest recommendation stays a hosted frontier model — today, that means a hosted frontier model through a runtime route not yet confirmed for customer work; the Codex adapter is available only in the technical sense `status.ts` states, and is not described as terms-compliant for customer work until OD-9 is resolved — not a local model stretched past its competence.

### 7.6 Privacy argument and its honest limits

The genuine, technical property local inference provides: text in that model's context window does not need to leave the business's own machine to reach a third-party provider's servers during that specific inference call (09b §8). It is not, on its own: a compliance certification (HIPAA, PCI DSS, SOC 2 each require their own controls and audit, none of which local inference provides by itself); a guarantee against data leaving by other paths (backups, application logs, a runtime's own telemetry, a misconfigured share); or a guarantee of equal accuracy to a hosted frontier model (smaller open-weight models generally trail the largest hosted models on hard reasoning tasks — a real accuracy-versus-privacy tradeoff, not a wash). Any local-model sales conversation should carry this distinction explicitly, not imply "local means compliant."

### 7.7 Limits and what must be verified before quoting

Per-customer hands-on benchmarking (the only rigorous option 09b identifies) does not scale past the first handful of customers (Pillar 11). Before quoting any bundle: current street price for the exact SKU; the exact license of the exact model file and quantization at install time; a real tokens-per-second measurement on the customer's actual target model and hardware, not a single community data point; whether the workload is one local models handle well (§7.4); the customer's power/noise/placement constraints; and a plain-language statement of what "local" does and does not mean for the customer's specific compliance obligations, since Diomedes is not a compliance certifier. One unverifiable, anecdotal throughput report exists in the research for a large MoE model on a Strix Halo-class mini PC (roughly 16 tokens/second) — a single anonymous online comment with no stated method, not a benchmark, and not attributable to any named vendor here; it should not be repeated to a customer as a performance promise.

### 7.8 Self-hosting a model: dated break-even

A dedicated 2×H100 box rented on demand runs $3,874 to $17,698 per month (GPU-hour price × 2 GPUs × 720 hours; mid price $3.99 × 2 × 720 = $5,745.60) (ME-06 finding 5, rows 15-16). At the mid price, break-even against hosted APIs (box cost ÷ blended API price per MTok) is 24,192M tokens per month against a GLM-5.3-Flash-tier price and 2,873M against a Claude Haiku 4.5-tier price (ME-06 row 16). That token break-even is a lower bound on the volume that would justify self-hosting, because it sets a box serving gpt-oss-120b (Artificial Analysis Intelligence Index 12, ME-04 row 28) against the per-token prices of stronger models rather than a capability-equivalent one (ME-00 finding 19). Break-even volume depends only on the box's fixed cost and the API price; a faster serving engine raises the box's capacity (about 41,581M tokens per month at the benchmark's saturated burst throughput) but does not move break-even (ME-06 rows 10, 16, 20).

Converted to businesses (businesses = break-even MTok per month ÷ MTok per business per month; recomputed with node), the answer depends on tokens per business, and the two sources disagree:

- ME-06's assumed 5.5M tokens per business per month (10x agentic overhead) gives about 522 businesses against a Haiku-tier price and about 4,399 against a GLM-5.3-Flash-tier price; with a 60% committed-use discount, about 209 and 1,759 (ME-06 rows 19, 21).
- ME-00's conversion from `09_price-performance-data.json` workload profiles gives about 3.36M tokens per business at base (about 854 and 7,190 businesses) and about 33.6M under a 10x overhead (about 85 and 719). Those profiles are assumptions from a track with no Verification section and are low confidence (ME-00 Confidence and Derivations; `docs/research/2026-09-15-model-economics-and-agent-terms/scripts/tokens-per-business.cjs`).

Self-hosting a Diomedes supervisor model was not costed (ME-06 Implication 5). Operating costs (on-call, patching, evals, rollback, capacity planning) are excluded and scale with deployments (ME-06 finding 7). The roadmap bars requiring owned or rented always-on GPUs for first revenue (`docs/DIOMEDES_LIVE_ROADMAP.md` line 120). Local hardware is a privacy and control choice, not a cost saving: a local box's cost per token is several times the cheapest hosted API at every modeled usage level (ME-06 Implication 3, row 24).
