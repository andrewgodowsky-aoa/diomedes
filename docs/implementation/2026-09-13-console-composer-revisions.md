## Implemented

The thread composer now shares the Board's send-confirmation component. Before
an external-engine request it shows the instruction, destination engine, selected
account/billing disclosure, and the exact document names to be submitted. Cancel
keeps the draft and sends nothing. A late listing result cannot send or open a
confirmation in another thread, mode or route.

Ask revisions select supported documents named in the current message or the
owning task's name/description, using the existing project document listing and
Board selector. Explicit document attachments keep their existing inclusion.
No assistant prose, previous transcript, arbitrary path or unnamed project file
is used to expand the selection. The existing eight-file/128 KB limits are
retained, including room for attachments. A failed listing reports an error and
preserves the draft without sending. A filename followed by a sentence-ending
period now matches, while longer extensions and outside-project paths do not.

The server remains the authority for path validation, supported reads, actual
byte limits, sending consent, current egress authority, and subsequent writes.
No server, Trust, grant, receipt, adapter, or credential code changed. Codex
Ask/Plan still follow the existing sending preference; Codex Build/Fix and the
external engines retain their required confirmation. Sample sends directly.
Sending grants no additional write authority. Ask does not change project files.

The Journey A driver now accepts the new send confirmation and reports the
sources recorded on this revision's user turn instead of repeating the previous
failure description. Historical journey evidence was not rewritten.
