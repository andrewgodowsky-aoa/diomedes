## Method

1. I read each record and the code it names. For each feature I looked for the failure classes the
   work order lists:
   - effect-admission bypasses;
   - containment escapes;
   - uncertain-effect reconciliation;
   - loop termination and budget;
   - a delegate exceeding its parent's scope;
   - supervision false positives and skipped ladder steps;
   - a *Verified* without evidence;
   - restart durability.
2. I ran three sub-reviews in parallel, for H13, H15 and H17. They worked read-only or in scratch
   copies. Each confirmed its candidates with a scratch test and ran mutation passes against the
   lane's own tests. I reviewed H12, the H12×H13 seam and `ceb4836` myself.
3. For every finding I fixed, I wrote a test first and **showed it red** on the base behaviour, then
   fixed it and showed it green. Where a test passed only because of what it didn't assert, I
   mutated the code to confirm the gap, then tightened the test until the mutant died.
4. A finding whose fix would be a redesign, or would decide something that is Andrew's to decide,
   gets a precise proposed patch below instead of code.

### Not fixed (proposed patches)

**A. P1 — H15: a new run can start on a task whose supervision escalation is open.**
- **What happens:** `WorkService.start` (`server/work.ts:45-49`) refuses only while a run is live. A person's Start on a Waiting task with an open escalation succeeds.
- **Consequence:** it detaches the question. `task.needId` becomes `null`, and the task reads `changes-ready`.
- **After finding 7:** that run's drift is noted, not paused. A later Continue resumes the *old* run after the new one has already done more work.
- **Proposed patch:**

  ```ts
  // server/work.ts start(), after the live-run check (and the same check in NativeWorkService.start)
  const escalation = state.needs.find(
    (need) => need.taskId === taskId && need.state === 'open' && need.supervision,
  );
  if (escalation)
    throw new ApiError(409, 'Diomedes paused this task and is waiting for your answer. Continue, redirect or stop it first.', {
      code: 'supervision_escalation_open',
    });
  ```

  with a test in `tests/h15-supervision.test.ts` that starts the task again after `driftingRun()` and
  expects 409.
- **Why it isn't applied:** it adds a refusal to every start path (sample, native, conversation,
  Ready queue). That is an admission change the H15 owner should confirm, and the Ready queue
  already stays off a `needs-ok` task.

**B. P2 — H13: a delegate's spend is not charged to the parent's job cap or model-call budget.**
- **What happens:** the delegate adapter is built with `runId: child.id` (`server/harness/capabilities/native-loop.ts:597`), and `JobCaps` keys the cap by that id. Each child therefore gets a fresh per-job cap: one loop can spend about 3× the cap (the parent plus two delegates).
- **Budget:** the parent's `delegate:<n>` step costs 1 unit and 1 tool call, not the child's 4 model calls.
- **Proposed patch:** pass `requestId: request.parent.id` for the child's job ledger (the route adapter takes a separate `jobId`, defaulting to `runId`). Also charge the delegate step `cost: delegateBudget.units`, so the parent's budget bounds its children.
- **Why it isn't applied:** it touches `EngineService.loopAdapter`'s signature in a hot file.

**C. P2 — H13: a job-cap stop parks a call that was never sent.**
- **What happens:** `*_job_cap_reached` is thrown before sending (`server/engines/model-api-core.ts:570, 704`). RunService still treats any error on an external model step as `reconcile_required` (`server/harness/run-service.ts:189`).
- **Effect:** the cancelled run keeps `model:<n>` `reconcile_required`, which claims an unknown outcome for a call that never left.
- **Proposed patch:** have the adapter throw `new HarnessError(code, message)` with a new `notSent = true` flag. RunService's catch would then record `retry_wait` / effect `failed` for it. This mirrors the `outcomeUnknown` flag added for finding 9.

**D. P2 — H15, smaller items:**
- **Case-sensitive folder comparison:** with a declared scope of `docs/…`, `Docs/x.md` is critical scope drift on a case-folding disk. This is safe (it errs toward pausing).
- **Silent cap:** the 4096-record cap stops supervision silently (`server/supervision/service.ts:150`). It should log once and show "Supervision records are full" in the Supervision section.
- **Hardcoded client:** `decidedFrom` is hardcoded `'desktop'` (`server/supervision/service.ts:505`).
- **Correction racing the pause:** a queued correction can be followed by an escalation before the run ever saw it, when new evidence lands in the same turn.
- **Unconfirmed:** the harness bridge's `mirror()` may expire a supervision Need on a cancelled harness run if a late event arrives. I did not reproduce this.

**E. P2 — H17, two items:**
- **Binary outputs:** a binary output (`binary: true`) can never be Verified, because `readDocument` returns 415 and `outputs-intact` reads incomplete. This errs toward uncertain.
- **Review excerpts:** a reviewer pass judges bounded excerpts (`REVIEWER_MAX_EXCERPT_BYTES`), yet counts toward Verified "against exact bytes". The evidence sentence should say the review saw an excerpt.

**F. P2 — H12: residual gaps the H12 record already states.**
- These are the TOCTOU instant before `rename`, and the libuv environment floor. I confirmed both and found nothing further.
- While testing I observed that a freed inode number can be reused at once on Linux, so a delete-and-recreate between the rename and the identity check can pass it. It is inside the stated window.

## Decisions to revisit

- **H15 proposed default 6** ("raised once per task and issue"), taken together with admission that
  lets a new run start while the escalation is open. Either the start is refused (patch A) or the
  new run should be paused as well. Noting it (what this review shipped) keeps the evidence but not
  the pause.
- **H13 proposed default 2** ("the person chooses the delegate route at start"). The delegate route
  should be no less private than the parent's. Finding 3 enforces the sharing grant on reads, and
  patch B would make the parent's cap cover the children.
- **H12 decision 1** (any interrupted write is uncertain, idempotent ones included) is sound. With
  finding 1 it now also covers the loop's `propose_write`, whose own reconciler settles a crash from
  History.
