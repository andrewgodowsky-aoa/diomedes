## Result

The slice adds a constrained declarative OpenAPI fixture compiler and a host-local
MCP projection. Two unrelated specifications, a library catalogue and helpdesk
tickets, compile into fixture connectors and execute through the same
`ConnectionsService.invoke` and Runtime step path as the reviewed Connections
service. There are no connector-specific branches in the compiler.

The compiler regenerates the candidate from the bounded source document and
selection. Promotion requires both the exact candidate digest and exact source
digest. It rejects changed candidates, undeclared operations/resources, duplicate
fixture inputs, malformed fixture inputs/results, dangerous non-JSON data, and
schemas that do not survive the supported Zod JSON Schema round trip. The promoted
manifest preserves the source version, records the source digest as provenance
integrity, keeps `allowedOrigins` empty, declares fixture authorization only, and
uses schema values generated by `z.toJSONSchema` from the same Zod validators that
the adapter executes.

Fixture execution is exact-match and data-only. The host review binds each exact
input to an immutable result and one or more declared resources in a trusted
closure. Unknown valid inputs are refused. Returned results are cloned, and no
script, callback, OpenAPI extension, reference, server, credential, URL, or source
description becomes executable code.

The MCP projection uses the official installed TypeScript SDK
`@modelcontextprotocol/sdk` 1.30.0 with its `Server`, `Client`, and linked
`InMemoryTransport`. It creates no socket or remotely accessible listener.
Discovery calls `ConnectionsService.modelContext` and `status`, then confirms the
saved run binding still names the host-bound connection. Calls accept only the
operation's reviewed arguments; project, connection, run, allowed operations, and
resource scope stay in the host closure and service state. Every tool call goes
only to `ConnectionsService.invoke`; there is no second permission or dispatch
path. Invocation rechecks authority again, closing the discovery-to-call race.

The host registers `compiledConnectionDemoConnectors` in its existing
`ConnectionsService`. Listing returns copied inactive candidate previews with
source, candidate, and review digests. Activation accepts an exact candidate
digest, derives the instance ID/resources/operations from the built-in review,
and delegates current tenant/project/manage authority to `service.install`.
An existing instance is refused even when disconnected, so this helper never
silently resumes or reauthorizes one.

`runCompiledConnectionDemoRoundTrip` admits a read through the same service,
uses the official `Client` and linked `InMemoryTransport` against the MCP
projection, validates its discovery and JSON result, and calls
`service.finishRead` on that same run. It creates no second Store, Runtime,
service, identity mechanism, permission path, socket, or external effect.

## Durable request and retry semantics

The MCP JSON-RPC request ID is hashed into a Runtime step ID inside the trusted
run-bound projection. Distinct request IDs create distinct durable steps. Reusing
the same request ID with byte-equivalent canonical arguments returns the recorded
Runtime observation without executing the fixture again. Reusing it with changed
arguments reaches Runtime's existing intent-hash check and is refused.

The supported lost-response retry is therefore the same logical bound projection,
the same JSON-RPC request ID, and the same canonical operation arguments. The
installed SDK's in-memory client/server proof exercises this across a reconnect
with the same request ordering. A new request ID is a new read and may execute
again. This projection is intended for one logical host-local MCP client per
admitted run; concurrent unrelated clients must receive different admitted runs.
There is no blind retry after an ambiguous external effect because generated
connectors have no external effects.

## Limitations

- Supported source operations are selected GET operations with bounded inline
  object schemas and query parameters. References, servers, security, callbacks,
  request bodies, path templates, custom serialization, and writes are refused by
  the candidate generator or schema round-trip gate.
- This is synthetic immutable fixture execution. It has no production API
  transport, redirects, credentials, live freshness, pagination, webhooks, or
  provider health check.
- Fixture results emit no connection observations. Adding observation mappings
  requires a separate reviewed declarative mapping format.
- This does not implement natural-language connector discovery, review UI,
  production activation, authenticated MCP transport, or a public MCP endpoint.
- Low-level SDK `Server` is used because discovery must dynamically recheck current
  authority. It remains an official SDK API but is marked deprecated in favor of
  the high-level `McpServer`; the high-level static registry does not provide the
  required per-discovery authority hook in the installed version.
