WHAT IS NEW
  Rules that act while a task runs, a work loop you start from a task, a Git
  view for software projects, automations, a line-by-line review of every
  change, and updates that refresh your install. Now also on Apple silicon
  Macs.

  Rule triggers. Write rules in Settings > Rules for every project, or from
  the Trigger rules line under Project instructions in a thread for one
  project or one task. A rule watches what a Nectovia work loop run writes, or
  the tool it is about to use on a file, and can note it, ask the run to
  correct, hold the step for your go-ahead before it runs, or stop and ask
  you. A project rule can add to or tighten a rule written for every project
  but never loosen it, and the app shows the reason when it refuses one. Each
  time a rule acts, it shows in the run's Supervision section.

  Start a Nectovia work loop run on a task with Loop run in the task's work
  panel. It offers only the routes that are ready, asks before a route sends
  anything off this computer, and opens the run so you can watch it plan, act
  and check.

  Software projects get a Repository section at the top of Files when the
  Software Engineering pack is on: the branch, changed files with a readable
  diff, and recent commits. It can add or remove a separate worktree on a new
  branch without touching your own checkout, and run the build and test
  commands you declare, asking you every time. A task whose check is one of
  those commands can be Verified on that result.

  Updates now refresh your install the first time the new version opens.
  Settings you never changed move to the new defaults, anything you chose is
  kept, cached screens are cleared, and a byte-for-byte backup and a record of
  what moved are kept. A custom look keeps its colours, fonts and artwork,
  while text sizes, line spacing and density follow the new version. You see
  it once: Updated to 0.2.0, with how many settings moved.

  A Mac build for Apple silicon (M1 and later) is published beside the Windows
  installer.

  Automations. Open Automations from the Nectovia group or Ctrl K. The weekly
  brief is listed there, and Run once runs it now. Owners and admins can turn
  on a schedule, pause it, resume it or turn it off; the screen shows the next
  three runs and any that were missed or skipped. Saving a schedule does not
  turn it on.

  Review what a task changed before you keep it. A task's thread shows each
  change line by line, and you can keep or undo each one, keep or undo them
  all, or send notes back with Revise with these comments.

  Approvals you give often can be remembered. After you approve the same step
  three times in a project, Nectovia asks whether to stop asking. Remembered
  approvals are listed in the Task permissions dialog, where Revoke takes any
  of them back.

  Ready work can start by itself. A switch on the Board, off until you turn it
  on, starts ready tasks automatically, and Pause queue or Pause all stops
  that again.

  Files you drop or paste into a project land in its Imports folder. Pictures,
  CSV files and the first sheet of an Excel file show as previews, a file's
  older versions can be opened, and Attach adds a file to a thread.

  A run's result now says whether it was checked: Verified, Not verified,
  Failed verification or Verification uncertain, in the thread and on the
  Board, with Run checks and Verify again.

  Running work has more controls. Stop options offers ways to stop a request,
  and Resume, Retry, Fork and a Steer box work on ChatGPT (Codex) runs.

  On the Nectovia home conversation, Claude Code keeps its session between
  messages. While an answer is being written you can queue your next message,
  and Stop ends the answer cleanly.

  Settings > Agent profiles saves a route, an exact model and an effort
  setting as a profile, and a project can list which profiles its work uses,
  in order.

  A Context used line under replies on the AWS, Azure, OpenRouter and Google
  Cloud routes shows what was sent to the model and what was summarised to
  fit.

  Project instructions now include instruction files in subfolders, and a run
  shows exactly which files it received, with Open in Files.

  Nectovia can suggest edits to a project's instruction files. You approve or
  decline each one, and can roll back to before any of them.

  Run details have a Supervision section that flags a run drifting away from
  its task.

  Capability packs can be installed, turned off, updated, rolled back or
  uninstalled from the Task permissions dialog, including a pack from a folder
  on this computer. With the Small Business pack on, Ctrl K can open a
  playbook to read it as well as use it.

  Conversation text size can be set to 90, 100, 110 or 125 percent under
  Settings > Appearance or from the ··· menu.

  The Windows icon, the installer, the Start menu entry and the window title
  now say Nectovia. The install folder and the program file keep the Diomedes
  name, so an update still finds your projects.

  Settings > What's new lists what every release changed, and after an update
  Nectovia shows the new version's notes once. When Check for updates finds a
  newer version, its notes appear before you download it.

FIXED
  Unsaved writing is no longer lost when you leave the editor another way,
  such as through Settings, Projects, another file or the command palette.

  The thread header no longer shows a document's context as a percentage like
  4182 percent; it shows a size.

  Plan files no longer get broken names, task names no longer stop
  mid-thought, and the weekly brief no longer uses the whole setup sentence as
  its title.

  Italic text displays, and each choice in the Cloud sharing dialog sits on
  its own line.

  Stopping a tool on Windows no longer sometimes reports a clean-up failure
  that did not happen.

  Facts in Discovery can be corrected or retired again after their source file
  is edited.

  An installed tool that changes in place is noticed, and size limits count
  the real size of text in any language.

  At 200 percent zoom and in small windows the work area and the inspector are
  usable again, and the Interface detail menu closes with Escape.

  Two windows sending the first message in a new project at the same moment no
  longer makes one of them refuse its own message.

LIMITS
  Unsigned and experimental. On Windows, SmartScreen may warn before the
  installer runs: choose More info, then Run anyway, after checking the file's
  SHA-256. The Mac build is signed ad hoc, not with an Apple Developer ID, and
  is not notarized, so the first time you open it, right-click the app and
  choose Open, or allow it under System Settings, Privacy and Security.

  The Mac build is for Apple silicon only; there is no Intel Mac build. It was
  built and launched on a GitHub-hosted Mac, not on a person's computer, and
  it does not install updates itself: Check for updates says when a new
  version exists, and you download it from the release page.

  Nothing in this version was tried against a real provider. Every route in
  its tests was scripted or fake, including Codex, Claude Code, OpenCode, AWS
  Bedrock, Google Vertex AI, Azure OpenAI and OpenRouter.

  Some parts are new and have not yet had an independent review: suggested
  edits to instruction files, playbook reading, the zoom and accessibility
  fixes, the Repository section, the update refresh, the Rules screens and
  Loop run. Rule triggers themselves were reviewed and the problems found were
  fixed.

  Automations run only the weekly brief, only while this computer is on, and
  tell you only inside the app: nothing is sent by push, email or phone.

  Resume, Retry, Fork and Steer work on ChatGPT (Codex) runs only. Claude Code
  keeps its session on the home conversation only, not in project threads.

  Run checks run only the checks a task declares, and never run your project's
  own code. Nothing checks a run automatically when it finishes.

  Files has no PDF viewer. Pictures and PDFs cannot be sent to an AI, and a
  binary file cannot be put back from an earlier version.

  Rule triggers watch Nectovia work loop runs only. Work on Codex, Claude
  Code, OpenCode and other outside tools is not watched, and a rule that asks
  a loop run to correct cannot reach it yet: the correction is recorded and
  shown as not sent. Loop run is in the task's work panel, which the
  Conversation view hides.

  Helpers that take pieces of a loop run's work, each in its own copy of the
  files, and a lead that runs a small team of them are built but cannot be
  started from the app yet.

  The Console still has no History screen, no Make tasks from this plan and no
  Stop for a conversation.

  This app is not signed in to a Nectovia account, and every route runs on,
  and is billed to, your own account.
