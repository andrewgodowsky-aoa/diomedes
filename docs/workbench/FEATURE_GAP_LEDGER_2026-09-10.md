## Upstream interpretation limits

Primary pages were refreshed during this inspection. Amp documents distinct safe-point steering, end-of-run queueing and interrupt. Vibe Kanban explicitly collects inline comments into the next message. OpenCode Go is a provider/subscription route, not an executor. Codex describes automatic review as a separate reviewer at existing boundaries. Claude's schedule documentation describes a bounded catch-up run after sleep. These are comparisons, not inherited Diomedes guarantees.

The two OMH repositories are separate projects. Their README workflows are descriptive evidence; no third-party harness was executed or integrated here. The witt3rd README itself identifies missing memory integration and sometimes prose-only verifier tool scoping. OMP's checked-editing approach needs a relevant benchmark before adoption. AionUi's format-preview list and Omnigent's policy examples are README claims, not Windows containment or performance proof. No external implementation was copied into Diomedes.

## Selected scope and proof boundary

The selected capabilities are **the saved run inspector** and **the Board projection of durable execution state**. They reuse existing Session/Task/Need/History and scrubbed HarnessRun records. They create no new scheduler, model calls, permission authority, mutation writer or provider fallback. Combined verification belongs to the isolated integration candidate.

### Implemented local slice

- `client/workbench/RunInspector.tsx`, `run-evidence.ts`, `workbench.css`: lazy read-only details using existing project-scoped GET routes. Saved origin uses `shared/attribution.ts`; past grant authorization is distinct from an exact human decision. Sources preserve path/hash revisions. Project/session keys, cancellation and returned ownership checks prevent cross-task evidence reuse. No raw prompt, step input/output, provider transcript or secret value is rendered. Unknown execution environment, effective-rule/skill snapshots, tokens and spend remain explicit; counted model/tool calls and unenforced wall-time metadata are distinct.
- `client/workbench/task-evidence.ts`, `client/console/BoardView.tsx`, `board.css`: queued/working/waiting/terminal Session state reconciles stale task mirrors; a later explicit Reopen still wins. Open approvals/results remain review work. Waiting Sessions reserve the existing execution slot. Stop invokes the unchanged owned Stop path, and an active uncertain effect has no Retry/Route action. Done says whether a person marked it or a run finished; it never asserts machine verification. No drag or render path starts work.

### Integrated verification

The authoritative final counts, commands and package identity are in
`docs/implementation/2026-09-10-autonomy-workbench.md` and
`evidence/autonomy-workbench/verification-summary.json`. Earlier handoff counts
and the temporary ES2022 test error have been superseded.

Deterministic coverage includes queued/working/terminal and stale mirrors;
explicit reopen/manual completion; waiting-slot display; unavailable, ambiguous
and changed run ownership; failed authorization/cancellation; source revision
deduplication and scope; escaped historical attribution; and render paths making
no mutation calls. The sidebar now uses the same task projection and preserves
the recorded actor after completion. Per-step origins propagate through the
existing Runtime bridge; legacy records remain without invented metadata.

`tests/autonomy-ui.spec.ts` exercises real application routes and Store writes
with synthetic generation: exact approval, confirmed same-task multi-file scope,
an actual folder boundary, revocation, Stop, inspector expansion/Refresh, stale
saved-approval reporting, and long names at 800px. `scripts/autonomy-desktop-smoke.mjs`
exercises an isolated Windows candidate and its compiled backend, including
History and final file hashes. Model generation is explicitly synthetic in both.
There is no live supervisor, live steering, scheduler or general containment proof.
